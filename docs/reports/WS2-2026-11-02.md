# WS2 (routing solver): night report, 2026-11-02

Branch `ws2-solver`. Scope: `packages/solver/**` only. Main (f5a7aee, on-chain research) merged in.

## Fait

- **`solve(input, opts)`** (`src/solve.ts`). Deterministic, no LLM. All money math is bigint (`src/math.ts`); floats are used only to turn `refRates` into fixed point and to present bps.
  1. **Guards that need no quotes.** tokenOut must be in the registry, verified and priced. If the invoice is worth more than `capUsd` (default 200), the result is `over_cap`.
  2. **Candidates.** One candidate per held token that is not excluded, is verified and has a price. Candidates are sorted by address.
  3. **Path per candidate.** When the held token is tokenOut, the path is `"0x"` and the cost is 0. Otherwise the solver tries direct paths on fees 100/500/3000/10000 and two-hop paths through each hub (default: the registry's USDT, configurable). It keeps the cheapest exact-output quote at the full amount, or at 1/N of it if no path can deliver the full amount. A quote that fails counts as no route.
  4. **Cost curves.** Exact-output quotes at k/N of the invoice (N = 10), plus one capacity quote: the maximum output from the whole balance with the margin kept aside. This is how depth and balance limits are applied.
  5. **Options.** Every single leg; the optimal 2-leg and 3-leg grid split (exact DP); a greedy fill by marginal cost, bounded by balance and depth; and the naive route. Every option is re-quoted at its exact amounts, so the reported cost is never a grid approximation.
  6. **Choice.** The solver picks the lowest `cost + legPenaltyBps × (legs − 1)` (default penalty 5 bps). Ties go to fewer legs, then lexicographic order.
  - **amountIn** = exact-output quote + ceil(margin), where margin is `maxSlippageBps` (default 50). Same-token legs have no margin. `quotedOut` is the output target of the leg, and the sum of `quotedOut` equals `amountOut`.
  - **Cost** = (USD in at the quoted, pre-margin amountIn − USD out) / USD out. The margin is not counted as a cost because the router swaps it too and refunds the surplus to the payer.
  - **naiveCostBps.** The largest-USD balance paying the whole invoice via the cheapest direct pool. If no direct pool exists (USDC/USAT), it falls back to the two-hop path. It is null when that route is infeasible.
  - **PullKind.** The first entry of the registry's `pullKinds`, except that PERMIT2 is used only for tokens listed in `opts.permit2Ready`. Otherwise the solver takes the next kind.
  - **Price guard (per leg).** A leg is refused when |USD in − USD out| / USD out > threshold. The check is two-sided: a pool that is suspiciously cheap is refused too. A single bad asset is skipped. `price_guard` is returned only when a plan exists without the guard and none exists with it.
  - **Fallback.** `direct_wfiat` if the payer holds any tokenOut, otherwise `ripio`. The solver never throws for business outcomes. It throws `RangeError` only for programming errors (amountOut ≤ 0, slippage outside 0–5000).
- **`createUniswapQuoter(client, quoterV2)`** (`src/quoter.ts`).
  - It calls QuoterV2 `quoteExactInput` / `quoteExactOutput(bytes,uint256)` through eth_call (`readContract`). The ABI declares them `view` on purpose so that a client created with `batch: { multicall: true }` sends one RPC round-trip.
  - The exact-output path is **reversed** inside the adapter, so the `QuoteSource` keeps swap-direction paths.
  - Any failure becomes `QuoteFailedError`.
- **`src/fx.ts`.**
  - `fetchReferenceRates()` caches for 60 s, times out after 3 s per source, rejects values outside sanity bounds, and dedupes calls already in flight. It never throws.
  - When every source for a currency fails, the currency is omitted, unless a cached value younger than 10 min exists.
  - **ARS uses the "dólar cripto" rate**: dolarapi `/v1/dolares/cripto`, falling back to the CriptoYa median.
  - BRL uses AwesomeAPI, then br.dolarapi, then open.er-api.
  - `createReferenceRateSource(opts)` accepts an injected fetch and clock for tests.
- **`src/simulator.ts`.** A deterministic constant-product pool simulator with fees, a depth limit (`maxOutBps`) and Uniswap rounding. `poolFromPrice()` is a helper for building pools.
- **Tests: 44, all green.**
  - 30 unit tests: same token, single swap, decimal normalisation, slippage, savings, insufficient balance, exclusions, 3-leg limit, split cheaper than single, leg penalty, depth, guards in both directions, wBRL per-currency guard, cap, no_route, quoter down, missing rate, unverified tokens, injected clock, determinism (including shuffled and lower-case balances).
  - 3 fast-check properties, seeded, 300 runs, which exercise 1, 2 and 3 legs. They check:
    - the chosen plan never costs more than a brute-force best single leg;
    - the sum of `quotedOut` ≥ amountOut;
    - every leg's amountIn ≤ its balance, there are at most 3 legs, tokens are distinct, and path endpoints are correct;
    - every executed leg is within the guard;
    - the result is deterministic.
  - 10 tests for the adapter (path reversal), FX (cache, fallback, stale value) and simulator.
  - 1 test replaying real mainnet quotes.
- **Real quotes.** `pnpm --filter @cobra/solver replay` (read-only, eth_call on forno) recorded 486 quotes at block 81,746,717 into `test/fixtures/real-quotes.json`. `test/replay.test.ts` reproduces all 30 recorded results bit-for-bit, offline.
- **Dependency:** `fast-check@4.10.2` (dev, pinned), for the property tests the brief asked for.

| wARS, USDT only | 8.1 | 10.7 | 36.9 |

| wBRL, USDC only | 212.9 | 224.9 | 346.2 |

USDC is about 11 bps cheaper than USDT because USDC trades rich in the USDC/USDT pool. At the production cap (≤ 200 USD), savings on wARS are a few bps. They become significant at ≥ 5k USD, and on wBRL because its pool is shallow.

## À relire

- **Price-guard defaults (proposed).** Each payment's guard comes from the first of these that is set: `maxPriceDeviationBpsByCurrency[tokenOut currency]`, then `maxPriceDeviationBps`, then the built-in default (`{ BRL: 350 }`), then 200.
  - **BRL: 350 bps.** Measured wBRL cost is 213–236 bps at ≤ 500 USD because the pool is one-sided at about 5.319 against a 5.437 market. A 2% guard would refuse every Brazilian payment.
  - **ARS: 200 bps, with the cripto rate required.** With the official rate (~1535), the guard refuses every payment, and a test covers this.
  - A global `maxPriceDeviationBps` that the caller passes explicitly overrides the BRL default.
- The naive route is "largest USD balance, direct pool". It falls back to two hops when no direct pool exists, which is always the case for USDC and USAT on Celo. Without that fallback, `naiveCostBps` would always be null for USDC holders.
- The fallback rule for "holds tokenOut but not enough…" is read as: any tokenOut balance gives `direct_wfiat`, otherwise `ripio`. This also applies to `over_cap` and `price_guard`.
- `costBps` can be **negative**. It is relative to `refRates`, so a USDC payment can come out "cheaper than the reference".
- Quote failures from an RPC outage are reported as `no_route` / `insufficient_balance` (the detail field counts the failed quotes), not thrown.
- **RPC load.** A USDC payer costs about 30 eth_calls: 20 path probes, 10 grid points and 1 capacity quote, with at most 8 in parallel. The web API should create its client with `batch: { multicall: true }`. `feeTiers: [100]` cuts this to about 12 calls, since every verified pool is on the 0.01% tier.
- `quotedAt` is read before the quotes are fetched, so `expiresAt` is conservative. `expiresAt` is not capped by `invoice.deadline`; the API/router enforce that.
- **Interpretation note.** USDT now defaults to EIP3009 (registry updated by WS0). wFIAT legs use ALLOWANCE unless the token is in `permit2Ready`, and ALLOWANCE requires the payer to send the tx (router `PayerMustBeSender`).

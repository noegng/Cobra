# WS3 — relayer, signer, agent identity, worker (2026-11-02)

## Fait
- `packages/relayer/src/signer.ts`: this is the only code path that signs. The guarded client accepts only `to == router` with value 0, and the calldata must be a fully decoded `pay()`. Before every send it checks the kill switch (env or flag), the USD caps (per payment, and a rolling 24 h sum of relayed invoices; an unknown token or a missing rate means a refusal), and it adds the ERC-8021 tag with `withAttribution(code)`. Setting `ATTRIBUTION_WALLET_CODE` switches to the Schema 2 tag `{app, wallet}`. The key is held in a closure. The exposed client has a json-rpc account, and every other signing method on it is blocked. An `onSigned` hook saves (hash, nonce) BEFORE the broadcast. `createRegistrationSender` can only send `register(string)` to the ERC-8004 IdentityRegistry.
- `relayer.ts`: claims work atomically (conditional UPDATE … SKIP LOCKED). Before sending it revalidates: the invoice is open and outside a 30 s margin, the quote is valid and its legs match, and every signature recovers off-chain to the payer (`verify.ts`, using the shared typed data with the token domain from TOKENS, or the on-chain DOMAIN_SEPARATOR as fallback). Then it simulates, moves the invoice open→submitted, and signs, persists and broadcasts. The watcher handles three outcomes:
  - revert, or a nonce consumed without `isPaid` → failed, and the invoice goes back to open;
  - a stuck or dropped tx → replaced on the SAME nonce with fees raised 25%;
  - success → left to the indexer.

  On restart, `sending` rows without a hash are requeued, and rows with a hash are watched again. Every status update is conditional, so the indexer's `confirmed`/`failed` is never overwritten. The relayer alerts the operator when the gas balance is low.
- Worker: env validation (exit 78), JSON logs, `level=alert` logs forwarded to the operator, graceful shutdown, systemd unit, README. Cap rates come from `@cobra/solver`'s `createReferenceRateSource`.
- `scripts/agent/register.ts` prints a dry run by default. `docs/agent/registration.json` is generated with the placeholder host `cobra.example`.
- Tests: 25 relayer tests (anvil + PGlite + mock router) and 3 worker tests.
- New dependencies: `@celo/attribution-tags@0.5.0` (ERC-8021), and `drizzle-orm@0.45.4` (same instance as `@cobra/db`).

## À relire
- The worker sends operator alerts with `Notifier.text(operatorChatId, …)`, but that signature expects a merchantId. WS4 has to accept an operator chat id.
- Per-day caps use a rolling 24 h window, and only count relayed submissions.
- Replacements skip simulation, so the nonce is still used up even when the tx reverts.

## Bloqué
- CI: the `ts` job has no foundry, so the anvil tests are skipped there. Add `foundry-rs/foundry-toolchain` to the job (WS0).

## Interface changes
None. `startRelayer` now requires `walletClient` to come from `createRelayerSigner` (this is enforced at runtime).

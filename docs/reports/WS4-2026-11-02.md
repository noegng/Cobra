# WS4 — Bot Telegram + agent (2026-11-02)

## Fait
- `packages/bot`: grammY bot. It handles onboarding (/start, language from `language_code`, country → wFIAT from TOKENS, payout address checked with checksum, slug, static QR) and the commands /cobrar /facturas /cierre /retirar /idioma /ayuda (es/pt/en aliases). State is stored in `flags`, so it runs on serverless.
- `amount.ts`: deterministic es/pt/en parser with typed errors (ambiguous, foreign_currency…).
- Regex fast path: "cobrar <amount> <desc>" never calls the LLM.
- Agent (AI SDK 7, `COBRA_MODEL`, default `claude-haiku-5-5`) with 7 zod tools. The merchant comes from the Telegram id. No tool moves funds.
- A payout address change requires a button tap.
- Injection guard: if the model calls a tool that doesn't exist, its text and its payout proposal are dropped.
- Pasted keys and seed phrases are intercepted before the LLM sees them.
- Invoices: wFIAT 1:1, A-NNNN references, rate limit of 10/min.
- QR PNG and a wa.me share link.
- Notifier, runReminders (once, 3 min before expiry), runDailyClose (`daily_close:<id>:<date>` + CSV).
- Voice notes plus the Groq adapter (done before the budget limit).
- 150 offline vitest tests.

## À relire
- Ripio: `buildRipioOfframpLink` returns null without RIPIO_PARTNER **and** a session-token minter, which is not implemented. Without it, the bot gives manual instructions.
- The proof-of-wallet-ownership link `/m/<slug>/verify` is a TODO for WS5.
- The LLM is stateless (no conversation history).
- The LLM rate limit is in-memory only.

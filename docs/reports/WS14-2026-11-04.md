# WS14 — payeur EIP-7702 (2026-11-04)

## Fait
- Repro sur fork anvil de Celo (`packages/shared/scripts/repro-7702.ts`, clé publique anvil #0, code `0xef0100…`) :
  - EIP-3009 USD₮ : revert `TetherToken: invalid signature`.
  - EIP-3009 USDC : revert `FiatTokenV2: invalid signature`.
  - Permit2 (permitTransferFrom, même SignatureVerification que la variante witness) : revert sans raison (code > 0 donc chemin ERC-1271, le delegate ne renvoie pas le magic value), pour USD₮ et USDC.
  - Même compte avec `setCode(0x)` : les 4 cas passent.
  - ALLOWANCE ne marche pas via relayer : le routeur exige `msg.sender == payer` (self-submit), et `/submit` le refuse.
- **Revu par l'orchestrateur (même nuit)** : le premier correctif refusait *tout* payeur délégué à la quote. Or avec
  le délégataire MetaMask (`EIP7702StatelessDeleGator`, `0x63c0c19a282a1B52b07dD5a65b58948A07DAE32B`, présent sur Celo),
  les 4 cas **passent** sur le fork (son `isValidSignature` fait un ecrecover de l'EOA). Seuls les délégataires
  « sweeper » (ceux des clés anvil) rejettent. Un refus en bloc aurait donc bloqué les comptes intelligents MetaMask.
- Correctif retenu : contrôle **au submit, par jambe**. Si le payeur est délégué (`eth_getCode` = `0xef0100`+20
  octets), on appelle `isValidSignature(digest EIP-712 exact, signature)` sur le compte (`eth_call`), comme le fera le
  token ou Permit2. Réponse ≠ `0x1626ba7e` ou revert : 422 `smart_account_unsupported`, rien en file. Erreur RPC : 502
  (le payeur réessaie). Sinon (non délégué, ou MetaMask) : rien ne change. La page affiche le message traduit es/pt/en.
  Pourquoi : `verifyTypedData` de viem retombe sur ecrecover, il acceptait donc la signature et l'échec n'arrivait qu'à
  la simulation du relayer, avec une erreur générique.
- Tests : 4 dans `apps/web/test/api.test.ts` (délégataire qui rejette, qui accepte, EOA, erreur RPC, désignateur) ;
  web 63/63, typecheck web vert.

## À relire
- `ApiDeps.delegatedAccountAccepts` est optionnel (absent = pas de contrôle) ; branché dans `apps/web/lib/server/deps.ts`.
- Coût : 1 `eth_getCode` par jambe au submit (+ 1 `eth_call` si délégué). Rien à la quote.
- Le payeur avec un délégataire qui rejette signe d'abord, puis reçoit le message (impossible de le savoir avant la
  signature sans connaître le délégataire). Une liste blanche de délégataires connus éviterait ça, mais exclurait les
  autres wallets par défaut.
- `repro-7702.ts` teste maintenant les 3 cas : sweeper, MetaMask, EOA simple.

## Bloqué

Interface changes : aucun (types partagés, schéma DB et ICobraRouter inchangés).

# WS5 — web (payer page, dashboard, API) — 2026-11-02

Branch `ws5-web`. `pnpm --filter @cobra/web test` (22 tests, PGlite), `typecheck` and `next build` (Next 16.4.3, Turbopack) are green.

## Fait

- **API** (`apps/web/lib/server/api.ts`: framework-free handlers; `app/api/**/route.ts` are thin adapters, Node runtime):
  - `GET /api/invoices/:id`: the public view. An `open` invoice past its deadline is reported as `expired`.
  - `POST /api/invoices/:id/quote`:
    - Balances and `allowance(payer, PERMIT2)` are read in one multicall. This fails closed when a balance read fails.
    - The real solver is called with `batch: {multicall: true}`, `feeTiers: [100]`, `permit2Ready` and `createReferenceRateSource()`.
    - The plan is validated before use (known token, supported kind, path shape, minOut == amountOut).
    - The quote is stored as a `quotes` row. `toSign[]` uses `eip3009TypedData` / `permit2TypedData` with `legNonce(intentDigest)`, and `validBefore` / `deadline` = the invoice deadline.
    - Kill switch → 503. Solver outage markers ("N failed quotes", missing rate) → 503 `retryable`, with no fallbacks offered.
  - `POST /api/invoices/:id/submit`:
    - The typed data is rebuilt from the stored quote. Every signature is recovered off-chain, and low-s is enforced.
    - Checks the per-payment cap (USD legs) and the kill switch.
    - Inserts a `pending` `submissions` row. The live-submission conflict returns 409, whether caught by the pre-check or by the unique index.
  - `GET /api/invoices/:id/status` returns the status, the tx hash (payment, else submission) and the Celoscan link.
  - `POST /api/m/:slug/invoice`:
    - Strict parser: `4500` / `4500,50` / `4500.5`; thousands separators are rejected.
    - wFIAT settlement only, 1:1 with the currency, created with `randomInvoiceId()`.
  - `POST /api/telegram` (isolated in `lib/server/telegram.ts`): a constant-time secret check runs before the bot is built, then grammY `webhookCallback(createBot(...), "std/http", {secretToken})`.
  - Per-IP rate limits (in-memory). Logs carry whitelisted fields only.
- **Pages:**
  - `/pay/[id]`:
    - The header shows the merchant, the amount, the payout address (short; tap for the full address, plus a Celoscan link), the domain and a countdown.
    - Connection: injected first (auto-connect on MiniPay), then WalletConnect.
    - Shows the plan with per-leg cost, `costBps` and `savingsBps` as returned by the solver. Signs each leg in sequence, then submits, polls and shows the receipt.
    - Error states: expired, insufficient balance (direct wFIAT transfer, plus the Ripio button only with `RIPIO_PARTNER`), no route, retry.
    - Permit2 one-time approve button.
  - `/pay/m/[slug]`: amount entry, then redirect to the invoice.
  - `/dashboard?t=`: list of invoices, totals (WS6 `@cobra/db/queries`) and CSV export (WS6 `paymentCsvRows` / `toCsv`).
  - `public/.well-known/agent-registration.json` (ERC-8004 registration-v1, placeholder).
  - i18n es/pt/en: cookie > Accept-Language > the merchant's language, with a switcher.
- **ALLOWANCE mode** (`lib/allowance.ts`):
  - Sends `approve(router)` then `pay`, both with the ERC-8021 `toDataSuffix(NEXT_PUBLIC_ATTRIBUTION_CODE)` suffix.
  - Gas is paid through the fee-currency adapter (`CELO.feeCurrency`).
  - Wired in the page under "Pagar desde mi billetera". It has not been tested on-chain.
- **Dashboard token** (`lib/dashboard-token.ts`): the bot calls `signDashboardToken({ merchantId }, DASHBOARD_SECRET)` and links `${PUBLIC_BASE_URL}/dashboard?t=${encodeURIComponent(token)}`. The default TTL is 15 min. The format is documented in the file so it can be reimplemented.

## À relire

- The rate limiter is per serverless instance. Use a shared store if abuse shows up.
- `permit2Ready` = the Permit2 allowance covers the payer's whole balance of that token. This is conservative.
- The submit cap counts USD-kind legs only (≈ $1 each).
- The ALLOWANCE flow and the Permit2 approve need a real-wallet test on mainnet, run by a human.
- Root `pnpm-workspace.yaml`: I added `allowBuilds: "@reown/appkit": false`, because WalletConnect's postinstall is only a version check. Without it, `pnpm install` fails with ERR_PNPM_IGNORED_BUILDS.

## Bloqué

- Ripio: minting the partner token (`mintRipioToken`) is a stub, so the button stays hidden until `RIPIO_PARTNER` and credentials exist.
- Mobile wallets' `eth_signTypedData_v4` support (MiniPay in particular) is unverified. ALLOWANCE mode is the fallback.
- `createBot` (WS4): the webhook answers 503 until it exists.

## Interface changes

None to frozen files. The bot needs `DASHBOARD_SECRET`. Suggestion: move `dashboard-token.ts` into `@cobra/shared` so the bot can import it, because web → bot → web would be a dependency cycle.

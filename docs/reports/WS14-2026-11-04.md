# WS14 — payeur EIP-7702 (2026-11-04)

## Fait
- Repro sur fork anvil de Celo (`packages/shared/scripts/repro-7702.ts`, clé publique anvil #0, code `0xef0100…`) :
  - EIP-3009 USD₮ : revert `TetherToken: invalid signature`.
  - EIP-3009 USDC : revert `FiatTokenV2: invalid signature`.
  - Permit2 (permitTransferFrom, même SignatureVerification que la variante witness) : revert sans raison (code > 0 donc chemin ERC-1271, le delegate ne renvoie pas le magic value), pour USD₮ et USDC.
  - Même compte avec `setCode(0x)` : les 4 cas passent.
  - ALLOWANCE ne marche pas via relayer : le routeur exige `msg.sender == payer` (self-submit), et `/submit` le refuse.
- Correctif minimal : `/quote` détecte le payeur délégué (`eth_getCode` = `0xef0100`+20 octets, `isEip7702Delegation`) et répond 422 `smart_account_unsupported` avant tout calcul de plan. La page de paiement affiche un message traduit es/pt/en (revenir à un compte standard ou payer depuis une autre adresse).
- Tests : 3 nouveaux dans `apps/web/test/api.test.ts` ; `pnpm -F` web (62 tests) et `pnpm typecheck` verts.

## À relire
- `ApiDeps.isDelegatedAccount` est optionnel (absent = pas de contrôle) ; branché dans `apps/web/lib/server/deps.ts`.
- Un getCode de plus par quote (en parallèle du multicall) ; en cas d'échec RPC : 502 `upstream_unavailable`.
- Pas de contournement produit : un payeur délégué ne peut payer par aucune voie gasless.

## Bloqué
- Rien. Piste future : self-submit ALLOWANCE (le payeur envoie lui-même, `msg.sender == payer`) pour ces comptes, demande des changements UI.

Interface changes : aucun (types partagés, schéma DB et ICobraRouter inchangés).

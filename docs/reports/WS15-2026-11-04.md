# WS15 — remboursement réel + refus structurés (2026-11-04)

Branche `night-5-refunds-events` (base `verif/night-2026-11-04`).

## Fait

**5A — surplus réellement remboursé**
- `payments.refunded_out` (text, nullable) : somme des `Transfer` ERC-20 de `tokenOut` du routeur émetteur de `Paid` vers le payer, dans la tx. `"0"` si aucun, `NULL` si le reçu est illisible (le paiement est quand même marqué payé).
- `packages/indexer/src/refund.ts` (`fetchRefundedOut`, `sumRefund`, bigint uniquement). Le reçu est lu dans `indexer.ts` AVANT la transaction DB (aucun appel RPC dans `applyBatch`). `PaidLog.refundedOut` optionnel.
- /proof : `RouteEntry.refundedOut` ; si non null et > 0 : « Excédent remboursé (réel, on-chain) » ; si null : l'ancien libellé « cotisé ». i18n es/pt/en.

**5B — refus structurés**
- Table `agent_events(id, kind, code, at)` + index sur `at`. Aucune adresse, montant, id de facture, IP ni texte libre.
- Codes fermés (`AGENT_EVENT_CODES` dans `packages/db/src/schema.ts`) : `price_guard`, `no_route`, `cap_per_payment`, `cap_per_day`, `cap_per_merchant_day`, `cap_per_payer_day`, `self_payment`, `smart_account_unsupported`, `payer_blocked`, `refused_other`.
- Écrivain `packages/db/src/agent-events.ts` (`writeAgentEvent`, `agentEventRecorder`) : fire-and-forget, erreurs avalées + loguées.
- Sites câblés (dépendance optionnelle `recordEvent`) :
  - web quote : `self_payment`, `price_guard`, `no_route`, `cap_per_payment` (solver `over_cap`), `payer_blocked`.
  - web submit : `self_payment`, `smart_account_unsupported`, `cap_per_payment` (`over_cap`), `payer_blocked`.
  - relayer (`SignerRefusedError` au check et à l'envoi) : `cap_per_payment`, `cap_per_day`, `cap_per_merchant_day`, `cap_per_payer_day`, `self_payment`, autres -> `refused_other`.
- /proof : « Refus de l'agent (14 derniers jours) » par code, calculé dans `queryJournal` donc même cache que le journal. i18n es/pt/en.
- Câblage prod : `apps/web/lib/server/deps.ts` et `apps/worker/src/main.ts`.

**Tests** : indexer (reçu avec remboursement / sans / erreur -> null, stockage), web (chaque site, panne d'écriture sans effet sur le statut HTTP, agrégation /proof, rendu du remboursement réel), relayer (code enregistré, recorder qui jette sans effet). `pnpm test` et `pnpm typecheck` verts.

## À relire
- `kill_switch` (refus transitoire du signer) n'est volontairement pas enregistré ; côté quote seuls `price_guard`, `no_route`, `over_cap` sont comptés (pas `insufficient_balance`, qui n'est pas un refus de l'agent).
- Les anciens paiements gardent `refunded_out = NULL` (pas de backfill) : /proof affiche donc encore « cotisé » pour eux.
- Un refus web `payer_blocked` est classé `kind = submit` aux deux endroits (fonction partagée `payerBanned`).
- Les refus du solver ne sont pas dédupliqués : un payer qui réessaie compte plusieurs fois.

- **Revue de l'orchestrateur** : `no_route` n'est plus enregistré à la quote (c'est surtout un wallet vide, pas un refus
  de l'agent, et n'importe qui pourrait gonfler le compteur public de /proof avec une adresse vide). Reste possible :
  un tiers peut appeler la quote avec `payer = adresse du commerçant` et inscrire un `self_payment` (quote non
  authentifiée) ; borné par le limiteur de débit par IP. Docstring de `fail()` remise à sa place dans relayer.ts.
- Une ligne `agent_events` par refus, sans purge : volume faible, à purger plus tard si besoin.

## Bloqué
Rien. Les refus "gas grant" du relayer (`gas_grant_refused`) ne sont pas câblés (hors périmètre : pas un refus de paiement).
